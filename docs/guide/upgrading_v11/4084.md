## `faker.helpers.uniqueArray` now passes `FakerCore` to the callback

The `faker.helpers.uniqueArray` method takes a function reference (or an array) as its first parameter. Previously you may have written code like this to generate unique values:

```ts
faker.helpers.uniqueArray(faker.internet.email, 1000);
faker.helpers.uniqueArray(faker.string.sample, 10);
```

`uniqueArray` now calls that function with a `FakerCore` as its first argument. Methods that previously worked with no required parameters can therefore receive an unexpected value:

- In TypeScript, this is now a compile-time error.
- In JavaScript, the extra argument can cause unexpected behavior. For example, `faker.string.sample` could try to generate enormous strings and lead to out-of-memory errors.

Instead, wrap the call in a lambda:

```ts
faker.helpers.uniqueArray(() => faker.internet.email(), 1000);
faker.helpers.uniqueArray(() => faker.string.sample(), 10);
```

**Bad**

```ts
faker.helpers.uniqueArray(faker.string.sample, 10); // ❗
// In Typescript, this is now a compile time error
// Argument of type '(length?: NumberOrRange | undefined) => string'
// is not assignable to parameter of type 'readonly string[] | ((fakerCore: FakerCore) => string)'.
```

**Good**

```ts
faker.helpers.uniqueArray(() => faker.string.sample(), 10); // ✔
```
